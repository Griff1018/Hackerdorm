# Sample dataset notes — Enterprise Buddy (demo dataset)

**SYNTHETIC DEMONSTRATION DATA.** No real business, person, address, payment identifier or
transaction is described. Every screen, slide and report showing this data carries the same label.

Fictional business: a student-run campus snack & drink seller ("Campus Crumb", delivery area: a
university campus in Malaysia). Currency **MYR**. Period **2026-09-01 .. 2026-09-30**; as-of 2026-09-30.

## Files

| file | rows | origin |
|---|---|---|
| products.csv | 5 | hand-authored |

| inventory.csv | 5 | hand-authored |
| expenses.csv | 8 | hand-authored |
| materials.csv | 20 rows / **17 distinct materials** | hand-authored |

Only `sales.csv` is machine-generated; re-running the generator reproduces it byte-for-byte
(sha256 `e558629505228bd54086f53e036f030a887d7f416d8daf7022beabd8198c5ef6`), so the golden values
stay valid.

## Conventions

- One **aggregated line per product per day**. A real POS export would have several lines per order;
  this keeps the file auditable and is disclosed here.
- `order_id` groups the day's lines into orders of 1–3 lines.
- **September only.** The August rows were removed (Sprint 1 revision 4): they were only needed for
  a prior-period comparison, which is a should-have that is not built. Consequence: this dataset no
  longer demonstrates period-over-period comparison.
- `discount_amount` is a total for the line, not per unit.

the drafted promo post is for Iced Lemon Tea 500ml. P005 no longer carries a duplicate inventory
record, so its stock (34) is usable and the zero-sales scenario is visible rather than hidden
(Sprint 1 revision 1).
